# Штатный разбор без набора флагов

Исправленный разбор действует безусловно в библиотеке, обоих конструкторах
экспортера и Manager. Публичные свойства и чтение следующих ключей удалены:

| Удалённая настройка | Постоянное поведение |
| --- | --- |
| UseCorrectedValueParsing | Исправленные числа, даты, экранирование строк и статусы |
| UseStructuredDataParsing | Именованные сложные данные и резервное дерево неизвестных форм |
| UseCurrentEventNames | Расширенный каталог представлений событий |
| UseLatestDictionaryValues | Последние завершённые записи LGF, включая переименование и очистку |
| UseFinalTransactionStatuses | Исходы по уже доступным Commit/Rollback без ожидания будущих событий |
| UseStrictParsing | Проверки корректности и безопасных границ выполняются всегда |

Старые ключи в JSON игнорируются, включая false: они больше не возвращают
историческое поведение. Их следует удалить из конфигурации. Код, использовавший
эти свойства предварительных сборок, необходимо пересобрать без присваиваний.
В исходном upstream этих свойств не было. Старые ветки разбора, терявшие данные
и неверно интерпретировавшие статусы, удалены, а не скрыты за true по умолчанию.

Только UseEventContext остаётся отдельным
переключателем формата, по умолчанию false. При true Data получает JSON-конверт
с исходными кодами, данными и контекстом разделения. Без него сохраняется обычный
внешний формат Data, с исправленными скалярами и JSON сложных данных.

## Переход с прежних версий

Схема ClickHouse, типы и порядок 24 колонок, движок и ключи не меняются.
Меняются значения: числа больше не теряются, раскрываются кавычки, сохраняются
пробелы, сложные данные получают JSON, исправляются TransactionStatus и Event.
Перед обновлением следует проверить использующие их запросы и отчёты.
Уже подтверждённая история автоматически не перечитывается и не переписывается.
Четыре компонента старого курсора и ранее сохранённые позиции поддерживаются.

Индекс исходов использует только доступные записи, не ждёт будущего Commit/Rollback
и не буферизует события открытых транзакций. Ранее выданные события не обновляются.

Проверки не требуют отдельного строгого режима. Завершённая повреждённая запись
пропускается только после успешного сохранения оригинала в лог. Некорректная дата
события не подменяется годом 0001 и не отправляется в ClickHouse. Неизвестный код
события или новый формат Data сами по себе не являются повреждением: код и дерево
данных сохраняются. Текущий неполный live-хвост ждёт дописывания. Незавершённый
архивный хвост или потерянная граница диагностируются без продвижения курсора.
Без обработчика проблемных записей библиотека возвращает ошибку и сохраняет
позицию; сервисы экспортера подключают логирование автоматически.

## Checkpoint и диагностика

Checkpoint остаётся явной настройкой пути: библиотека не выбирает произвольный
постоянный каталог для чужой службы или контейнера. При отсутствии CheckpointFile
или CheckpointDirectory выводится Warning с источником, риском пропуска после
частичного INSERT и именами нужных настроек. Каталог нужно сохранять между
запусками. Дубли после неоднозначного INSERT всё ещё возможны.

Файловый логгер автоматически ротирует log.txt перед превышением 10 МиБ и хранит
пять архивов log.txt.1..log.txt.5; .1 — самый новый. Лимит считается в UTF-8 байтах,
сообщения не делятся. Запись больше лимита сохраняется целиком в отдельном файле,
поэтому 10 МиБ — мягкая граница. Общий размер зависит от размеров таких записей.
Старейшие архивы удаляются при ротации. Блокировка общая для категорий внутри
процесса; нескольким процессам нужны разные файлы логов. Ошибка записи/ротации
не считается успешным сохранением проблемной записи.

Production runtime и пакеты остаются прежними. Исполняемый ProcessHarness на
.NET 8 и Docker runtime нужны только регрессионным тестам аварийного восстановления.

## Проверка

Проверка удаления флагов 2026-10-12: 427 тестов читателя и 82 теста экспортера
с ClickHouse 26.8.15.10 LTS, без пропусков. Сокращение числа тестов связано с
удалением комбинаций старых режимов; сценарии курсоров, данных, ошибок, доставки,
убийства процесса и реального ENOSPC сохранены. Старые false/true и невалидное
значение удалённых ключей не отключают исправления в обоих конструкторах экспортера;
Manager также проверен со старыми false.

Все поля 452 190 событий девяти приватных снимков совпали с 0ab3958 при включённых
исправлениях и проверках, отдельно с контекстом и без него. SHA-256 всех 51 LGF/LGP
сохранился. Исходные журналы и приватные результаты не публикуются.

Три парных замера полного чтения с прогревом и переменным порядком сборок:
штатный разбор 4,218 → 4,036 с, с контекстом 6,145 → 6,125 с. Замеры на .NET 8,
Release, DOTNET_TieredCompilation=0, DOTNET_gcServer=0, без записи в ClickHouse.
Просадки не выявлено; небольшую разницу нельзя считать доказанным ускорением.

Исторические измерения до этого изменения сохранены в отчётах; старые комбинации режимов
относятся только к зафиксированным сборкам. Текущие benchmark default/current
используют реальное штатное поведение выбранной версии, context добавляет только
UseEventContext. Сравнение с upstream выполняет разный объём работы и не является
сравнением скорости одинакового набора функций.
