# Штатный разбор без набора флагов

По решению пользователя исправления разбора теперь включены по умолчанию в
читателе, обоих конструкторах экспортера и Manager. Для новой конфигурации не
нужно перечислять пять независимых переключателей:

| Прежняя настройка | Новое поведение при отсутствии настройки |
| --- | --- |
| UseCorrectedValueParsing | Исправленные числа, даты, экранирование строк и статусы |
| UseStructuredDataParsing | Именованные сложные данные и резервное дерево неизвестных форм |
| UseCurrentEventNames | Расширенный каталог представлений событий |
| UseLatestDictionaryValues | Последние доступные завершённые записи LGF, включая переименование и очистку |
| UseFinalTransactionStatuses | Исходы транзакций по уже доступным Commit/Rollback |

Из типовых appsettings эти настройки удалены. Для совместимости публичные
свойства и чтение старых конфигурационных ключей сохранены: явно заданный `false`
по-прежнему выключает соответствующее улучшение. Удалены также неиспользуемые
параметры очереди WritingMaxDegreeOfParallelism/CollectedFactor из примеров;
старые ключи и свойства продолжают приниматься.

`UseEventContext=false` остаётся отдельной опцией: её включение меняет внешний
формат Data и увеличивает объём. `UseStrictParsing=false` сохранён для клиентов,
которым нужна строгая проверка; в типовой конфигурации его больше нет. Логирование
завершённых проблемных записей в сервисах работает автоматически, а небезопасные
границы повреждённой записи по-прежнему не пропускаются.

## Переход с прежних версий

Схема ClickHouse, типы и порядок 24 колонок, движок и ключи не меняются.
**Значения полей при отсутствующих настройках меняются намеренно:** например,
число в Data теперь сохраняется, сложные данные получают JSON, исправляются
представления TransactionStatus и новые представления Event. Это требует проверки
запросов и отчётов, использующих прежние значения. Подтверждённая история не
перечитывается и не переписывается автоматически.

Если в старом appsettings уже перечислены `false`, они продолжают действовать.
Чтобы перейти на штатный улучшенный разбор, удалите эти пять ключей либо явно
задайте `true`. Для прежних представлений сохраните все пять значений `false`.
Частичный набор выключает только явно выбранные функции: например, выключение
исправления скаляров не выключает независимый индекс исходов транзакций.

Индекс исходов читает только доступные файлы, не ждёт будущего Commit/Rollback
и не буферизует события открытых транзакций. Выданные ранее события не обновляются.
Дополнительный разбор и индекс требуют времени и памяти; прежний облегчённый
режим и новый штатный режим следует измерять отдельно. Benchmark `default`
фиксирует старый набор со всеми флагами false, а `current` — новый набор из пяти
включённых функций, независимо от начальных значений свойств библиотеки.

## Checkpoint и диагностика

Checkpoint остаётся явной настройкой пути: библиотека не выбирает произвольный
постоянный каталог для чужой службы или контейнера. При отсутствии CheckpointFile
или CheckpointDirectory выводится Warning с источником, риском пропуска после
частичного INSERT и именами нужных настроек. Каталог нужно сохранять между
запусками. Дубли после неоднозначного INSERT всё ещё возможны.

Файловый логгер автоматически ротирует log.txt перед превышением 10 МиБ и хранит
пять архивов log.txt.1..log.txt.5; .1 — самый новый. Лимит считается в UTF-8 байтах,
сообщения не делятся. Запись больше лимита сохраняется целиком в отдельном файле,
поэтому 10 МиБ — мягкая граница. Общий размер зависит от размеров таких записей.
Старейшие архивы удаляются при ротации. Блокировка общая для категорий внутри
процесса; нескольким процессам нужны разные файлы логов. Ошибка записи/ротации
не считается успешным сохранением проблемной записи.

Production runtime и пакеты остаются прежними. Исполняемый ProcessHarness на
.NET 8 и Docker runtime нужны только регрессионным тестам аварийного восстановления.

## Проверка

439 тестов читателя и 104 теста экспортера прошли без пропусков; production
solution собирается с прежними предупреждениями net5.0. На девяти приватных
снимках сверены все поля 452 190 событий с предыдущей версией 7b64d50 при
одинаковых настройках, включая явно прежний режим, новые defaults, строгий
разбор и контекст. Расхождений нет; SHA-256 всех 42 LGP и 9 LGF не изменился.
Журналы и приватные результаты не публикуются.

Контроль скорости: .NET 8, Release, один прогрев и один замер на процесс,
три парных прогона с переменным порядком версий, DOTNET_TieredCompilation=0,
DOTNET_gcServer=0. Медианы полного чтения корпуса:

| Фиксированный набор функций | До, с | После, с |
| --- | ---: | ---: |
| Прежний облегчённый, все флаги false | 1,671 | 1,652 |
| Новый штатный, пять функций true | 4,121 | 4,046 |

Просадка при одинаковых функциях не выявлена; малая разница не доказывает ускорение.
Новый штатный режим примерно в 2,45 раза медленнее облегчённого на этом корпусе,
поскольку действительно выполняет дополнительный разбор и индексирование.
Это скорость читателя с прогретым файловым кешем, без записи в ClickHouse;
она не является замером production-службы на net5.0.
