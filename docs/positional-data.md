# Маскированные позиционные данные ЖР

Разбор включается только `UseStructuredDataParsing=true`. Колонки ClickHouse,
DDL и вывод при выключенном флаге сохраняются. Конверт находится в прежнем
`Data String`; при `UseEventContext=true` он является JSON-строкой поля `Data`
внешнего конверта контекста.

```json
{
  "$format": "1c-positional-data-v1",
  "layout": "P/192",
  "values": {"MaxUnsuccessfulAttemptsCount":"3", "LockDuration":"300"},
  "unnamedFields": [],
  "nodes": ["P", ["192", ["N", "3"], ["N", "300"]]]
}
```

Числа и логические значения — строки; D — локальное значение даты без
приписанного часового пояса, в форме `yyyy-MM-ddTHH:mm:ss`. Ссылки метаданных
O/# представлены как `{"$type":"O","typeId":"…","value":"…"}`. Их UUID
не разрешается в имя текущего объекта. Роли — массив таких ссылок, включая
пустой массив. `nodes` сохраняет разобранные токены целиком, включая исходную
дату, кавычки внутри строк и все неподтверждённые позиции.

## Пользователи

Поддержаны `_$User$_.New`, `.Update`, `.NewError`, `.UpdateError` с точными
формами **P/65535, 29 узлов** и **P/65534, 28 узлов** в теле P. Индекс 0 —
маска. Таблица указывает индексы в P/65535; P/65534 пропускает позицию 13,
поэтому индексы 14–28 в нём уменьшаются на единицу.

| Индекс | Имя в values | Проверка в тестовой базе |
| --- | --- | --- |
| 1 | OSAuthentication | АутентификацияОС, true/false |
| 2 | StandardAuthentication | АутентификацияСтандартная, true/false |
| 3 | CannotChangePassword | ЗапрещеноИзменятьПароль, true/false |
| 4 | Name | Изменение имени |
| 5 | Language | Выбор языка конфигурации |
| 7 | PasswordIsSet | Установка и очистка искусственного пароля |
| 8 | ShowInList | ПоказыватьВСпискеВыбора, true/false |
| 9 | FullName | Изменение полного имени |
| 10 | OSUser | Искусственное имя `\\FixtureDomain\FixtureUser` |
| 11 | RunMode | УправляемоеПриложение |
| 12 | Roles | Очистка/добавление тестовой роли |
| 14 | OpenIDAuthentication | true/false |
| 19 | Email | Искусственный адрес example.invalid |
| 20 | OpenIDConnectAuthentication | true/false |
| 21 | AccessTokenAuthentication | true/false |
| 23 | PasswordPolicyName | Имя тестовой политики |
| 24 | PasswordSettingDate | ЗаписываемаяДатаУстановкиПароля |
| 26 | QRCodeAuthentication | true/false |
| 28 | EmailAuthentication | true/false |

Не именованы позиции **6, 13, 15, 16, 17, 18, 22, 25, 27** P/65535;
их строковые индексы перечислены в `unnamedFields`. Позиция 6 менялась при
записи пароля, но не совпадала с PasswordIsSet. Названия остальных не назначены
по одному внешнему сходству значений. Для P/65534 список индексов пересчитан.
Таким образом, запись разобрана частично по смыслу и полностью сохранена.

Текущие формы создавались настоящей платформой 8.3.27.2325. Форма P/65534
наблюдалась в исторических журналах; искусственные тесты воспроизводят её
порядок, удаляя позицию 13 из контролируемых записей P/65535. Штатный экспорт
принимает обе формы, но не даёт независимых названий их полей.

## Параметры базы

Поддержаны `_$InfoBase$_.ParametersUpdate` и `.ParametersUpdateError`.
Именуются только следующие проверенные маски; порядок произвольных комбинаций
битов не предполагается.

| Маска | Поля по порядку | Контролируемая операция |
| --- | --- | --- |
| 1 | LockWaitTime | УстановитьВремяОжиданияБлокировкиДанных(47) |
| 64 | MaxUnsuccessfulAttemptsCount | БлокировкаАутентификации: число попыток 7 |
| 128 | LockDuration | БлокировкаАутентификации: длительность 61 секунду |
| 192 | MaxUnsuccessfulAttemptsCount, LockDuration | Одновременно 3 попытки и 300 секунд |
| 65536 | InactivityTimeForTerminateSessionNotification | УстановитьВремяПредупрежденияОЗавершенииСеансаПриБездействии(37) |
| 131072 | InactivityTimeForTerminateSession | УстановитьВремяЗавершенияСеансаПриБездействии(1200) |

В корпусе найдены маски 128 и 192. Остальные воспроизведены в изолированной
базе. Значения 60/3/300 сами по себе не использовались для угадывания имён.

## Парольная политика

`_$InfoBase$_.UserPasswordPolicyNew` и `.UserPasswordPolicyUpdate`: P/255,
десять узлов тела. Позиции 1–8 подтверждены раздельными присваиваниями свойств:
Name, PasswordMaxEffectivePeriod, PasswordMinEffectivePeriod,
PasswordMinLength, PasswordReuseLimit, PasswordStrengthCheck,
PasswordExpirationNotificationPeriod, PasswordCompromiseCheck.

Позиция 9 сохраняется как
`ActionOnPasswordRequirementsViolationOnAuthenticationCode` — числовой код
действия. Соответствие чисел элементам перечисления не объявляется проверенным;
код не преобразуется в предполагаемое название действия.

## Проверка и ограничения

Все имена относятся к установленным формам файлового протокола, а не к
документированному универсальному бинарному контракту платформы. Иные маска,
количество, типы, неправильная дата/UUID/логическое значение или нарушенный
массив дают полный `1c-brackets-v1` вместо частично ошибочных имён.

В тестовой базе перед каждым изменением пользователь заново загружался по
UUID: повторное использование объекта после записи пароля влияло на служебный
флаг позиции 6. В открытых fixtures сохранены только искусственные значения;
даты нормализованы. Ожидаемые значения задаются по выполненной операции,
независимо от библиотеки. Все 78 записей проверены штатным ibcmd 8.3.27.2325
с обязательным сравнением количества: он принял их и вернул `Data=null`.

В реальном корпусе 50 записей получили этот конверт, их исходные деревья и
курсор проверены отдельно. 106 пустых P обновления конфигурации/расширений
остаются пустым резервным деревом. Это не 106 неизвестных содержательных
форматов. Проверка каталога событий или этих fixtures не доказывает покрытие
всех вариантов будущих версий и CORP.

Пример запроса без изменения таблицы:

```sql
SELECT
    JSONExtractString(Data, 'values', 'MaxUnsuccessfulAttemptsCount'),
    JSONExtractString(Data, 'values', 'LockDuration')
FROM EventLogItems
WHERE JSONExtractString(Data, 'layout') = 'P/192';
```
