# Курсоры, обновления LGF и итоги транзакций

## Совместимость

ClickHouseStorage и публичная модель EventLogItem не изменены. Сохраняются 24
колонки, их порядок, типы и DDL, позиционная вставка, а также четыре компонента
курсора: FileName, EndPosition, LgfEndPosition и Id. Новых зависимостей, таблиц,
миграций и изменений target framework нет.

Исправление курсора действует всегда. Позиции теперь считаются по исходным
байтам UTF-8 без обращения к внутренним полям StreamReader. EndPosition указывает
сразу за закрывающей скобкой завершённой записи. LgfEndPosition снимается после
разрешения всех ссылок события. При незавершённой записи чтение возвращается к её
началу: после дописывания она читается целиком, включая разделённый UTF-8 символ.

Ранее сохранённые курсоры штатных LGF/LGP принимаются, в том числе LGP-позиции
со смещением +1 на разделитель. При восстановлении LGF допускается то же
смещение. Числовые позиции могут отличаться от прежних; смысл и порядок событий
сохраняются; представления значений теперь всегда исправляются. Старый LGF-курсор, снятый до
разрешения ссылок предыдущего события, может давать иную позицию словаря после
возобновления, чем непрерывное чтение. Это не требует изменения формата курсора.

## Штатное поведение

Обновления словаря и определение доступного исхода транзакции работают всегда.
[Правила перехода](defaults-and-upgrade.md).

Перед событием прочитываются все завершённые записи LGF и обновляются существующие
ключи. Учитываются переименование, заполнение пустого имени и очистка значения.
В архиве используются последние имена из доступного LGF. В live-режиме учитываются
дописанные записи, незавершённый хвост остаётся для повторного чтения.

N означает «Нет транзакции», C — «Зафиксирована», R — «Отменена». Для U ищется
Commit/Rollback в доступных LGP, включая другие периоды и записи до курсора или
SkipEventsBeforeDate. Ключ включает исходную дату транзакции без округления до
секунды, номер, соединение и идентификатор сервера. Без завершения — «Не завершена».
Словарь индекса отдельный; ожидания будущих событий и буфера открытых транзакций нет.

Индекс строится при первом U. Для архивной сверки следует использовать стабильную
копию полного набора LGF/LGP. В live-режиме для ещё неизвестного исхода индекс
дочитывает новые файлы и завершённые хвосты. **Результат относится к доступным
данным на момент чтения:** будущий Commit/Rollback не изменяет уже отданное
событие или строку ClickHouse. Для окончательных итогов всего архива нужен
завершённый архив. Ожидание будущих завершений и обновление ранее выгруженных
строк не реализованы; неизменная схема и вставки сохраняются.

Первое построение индекса требует дополнительного прохода по LGP. В памяти
хранятся исходы найденных транзакций и позиции файлов; расход памяти растёт с
числом транзакций. Непротиворечивый полный набор журналов важен: потерянный период
с завершением оставляет U незавершённым, а противоречащие друг другу исходы или
неразрешимая ссылка на событие вызывают ошибку. При ошибке индекса текущий элемент
остаётся для повтора, Id не увеличивается. Усечение файла обнаруживается при
обновлении словаря/индекса и требует перезапуска читателя. Подмена файла с тем же
именем и длиной автоматически не распознаётся.

Новый разбор не переписывает историю. В одной таблице могут остаться прежние и
исправленные значения. Дополнительные поля событий, представление ссылок
«Объект не найден», новые системные имена и CORP не входят в эти изменения.

## Проверки на локальных журналах

Проверены копии 42 LGP и 9 LGF из девяти файловых баз: 452 190 событий.
Эталон — ранее полученная штатная JSON-выгрузка ibcmd 8.3.27.2325; версия
платформы, которой исторически записано каждое событие этих баз, не установлена.
Оригиналы и выгрузки остаются локальными; в Git публикуются искусственные тесты
и агрегированные результаты.

| Проверка | Результат |
| --- | --- |
| Все значения по умолчанию против сборки f43ab67, кроме двух исправляемых позиций | 452 190 совпадений, 0 расхождений |
| LGP-курсор против независимого сканера исходных байтов | 0 расхождений во всех 7 комбинациях настроек |
| Смещения старого LGP-читателя +1 | 28 774; у нового читателя отсутствуют |
| Имена метаданных против штатной выгрузки с новым режимом LGF | Устранены 71 760 расхождений, включая очистку имени |
| Статусы против штатной выгрузки при corrected + final | Устранены 170 681 расхождение U → Committed; 0 оставшихся расхождений статуса |
| Возобновление: новые курсоры / старые курсоры / старые с новыми режимами | 279 запусков, 2 035 401 прочитанное событие; 0 пропусков, повторов и расхождений содержимого |

В трёх событиях одного возобновления старого курсора без новых режимов отличается
только LgfEndPosition: старый checkpoint не включал словарные ссылки предыдущего
события. Для новых курсоров и старых с обоими новыми режимами все 24 поля совпали
с непрерывным чтением.

С включёнными всеми четырьмя режимами не осталось расхождений сравниваемых
значений с платформой, кроме ранее выделенных различий контракта: представлений
пустых метаданных и несуществующих ссылок, сохранённых исходных сложных данных,
для которых платформа выводит null, и SessionDataSeparation вне текущей модели.
Это не заявление о полном покрытии всех полей и событий платформы.

Регрессионные тесты курсора воспроизводят три ошибки на прежней сборке:
смещения на границах буфера, потерю незавершённой записи и слишком ранний
LGF-checkpoint. Новая сборка проходит их. Дополнительно проверены Commit,
Rollback, незавершённая транзакция, разные соединения, точность исходной даты,
периоды, восстановление, частичные хвосты и повтор после ошибки словаря.

На ClickHouse LTS 26.8.15.10 проверены прежняя таблица, старый курсор,
исправленные значения и неизменность SHOW CREATE TABLE. Всего: 89 тестов читателя
и 30 интеграционных тестов, включая 6 тестов с реальным ClickHouse. Сборка
исходного solution проходит с четырьмя прежними предупреждениями о net5.0.
