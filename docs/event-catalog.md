# Представления системных событий

`Event` содержит точную русскую подпись штатной выгрузки 1С для известного
системного кода. Прикладное имя и неизвестный код возвращаются как записано
в журнале: пробелы, точки, регистр, кавычки и Unicode не нормализуются.
Сопоставление выполняется по полному коду с `StringComparer.Ordinal`.

## Источник

Каталог проверен независимым файловым `ibcmd eventlog export --format=json` на
искусственных LGF/LGP с фиксированной датой и пустыми Data. Проверены 151 код:
объединение прежних карт экспортёра, модели 8.3.27.2325 и дополнительного
каталога. Исходные пользовательские записи для fixture не используются.

- 136 подписей подтверждены `ibcmd 8.3.27.2325`.
- Ещё 10 событий ограничений профиля безопасности подтверждены `ibcmd 8.5.4.1878`.
- Для кодов, распознанных обеими версиями, различий подписей не обнаружено.
- Приоритет имеет 8.3.27.2325; 8.5.4 используется для добавленных позднее кодов.
  Настройка версии платформы для выбора названий не требуется.

[event-catalog.csv](event-catalog.csv) хранит подпись, версию и источник
каждого соответствия. `OneSTools.EventLog.Tests/Fixtures/event-catalog.json`
используется для независимых ожиданий в тестах читателя и ClickHouse.
Проверка представления не означает воспроизведения операции, вызвавшей
событие, или полного разбора всех вариантов Data.

## Коды без штатной подписи

Обе проверенные версии возвращают эти строки без локализации. Они сохранены
как есть; прежние предполагаемые переводы не используются:

- `_$Data$_.Pos`
- `_$Data$_.VersionCommentUpdate`
- `_$InfoBase$_.RegionalSettingsUpdateError`
- `_$User$_.AuthenticationUnlockError ` — с завершающим пробелом; правильный
  код без пробела имеет штатную подпись.
- `_$User$_.SecurityProfileChange` — присутствует в модели 8.3.27, но обе
  выгрузки сохраняют код. `_$InfoBase$_.SecurityProfileChange` имеет подпись.

Неизвестные коды с префиксом `_$` сохраняют прежнюю диагностику `UnknownEvent`.

## Переход

Новые подписи применяются при следующем чтении. Схема приёмника, курсор и
содержимое Data не меняются. Подтверждённая история автоматически не
перечитывается и не переименовывается. Для запросов по накопленной истории
нужно учитывать прежнюю и новую подписи. Прикладные названия, даже похожие на
русские системные подписи, не меняются. Сырой `EventCode` в необязательном
`UseEventContext` сохраняется.
