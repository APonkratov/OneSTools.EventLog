# Сложные данные ЖР без изменения таблицы ClickHouse

`UseStructuredDataParsing=false` по умолчанию сохраняет прежнее представление
сложных данных. Настройка независима от `UseCorrectedValueParsing` и передается
через EventLogReaderSettings, EventLogExporterSettings, конфигурацию одиночного
экспортера и Manager.

Фрагмент для включения обоих исправлений в существующей конфигурации:

```json
{
  "Exporter": {
    "UseCorrectedValueParsing": true,
    "UseStructuredDataParsing": true
  }
}
```

| Corrected | Structured | Поведение |
| --- | --- | --- |
| false | false | Исторические значения всех полей |
| true | false | Исправленные скаляры, экранирование и статусы; прежние сложные данные |
| false | true | JSON для сложных/неизвестных Data; остальные поля и известные скаляры прежние |
| true | true | Оба исправления |

Существующие 24 колонки, DDL, порядок BulkCopy, курсор и зависимости экспортера
не меняются. `Data` остается **String**, JSON записывается его содержимым.
Новая настройка применяется к будущему чтению и не переписывает историю.
При переключении режимов одна таблица может содержать разные представления Data;
старые отчеты, ожидающие `Item n: ...`, следует проверить перед включением.

## Подтвержденные именованные форматы

Имена полей назначаются только при совпадении исходного кода события, формы
блока, числа элементов и типов. Проверено на обычной 1С 8.3.27.2325 со штатной
выгрузкой `ibcmd eventlog export --format=json`.

| Событие | Проверенная форма P | JSON Data |
| --- | --- | --- |
| `_$Session$_.Authentication` | `518, S, S, N` | Name, CurrentOSUser, AuthenticationMethod |
| `_$InfoBase$_.ConfigUpdate` | `S, S`, без номера подтипа | Vendor, Version |
| `_$InfoBase$_.DBConfigUpdate` | `S, S`, без номера подтипа | Vendor, Version |
| `_$InfoBase$_.ExclusiveModeChange` | `2, B` с 0/1 | ExclusiveMode |
| `_$Access$_.Access` | `1, Z`: строковые колонки Pattern, ноль/одна/несколько строк | Data.Column и Data.Row |

Дополнительные формы AuthenticationError, расширений, внешних обработок/отчётов,
предопределённых данных и самоописывающихся P перечислены в
[доработке обычной платформы](noncorp-parsing.md). Для самоописывающихся данных
используется отдельный `1c-named-data-v1`, сохраняющий имена и исходное дерево.

Пустые значения сохраняются. Число метода аутентификации и логическое значение
монопольного режима представлены строками, как в штатной JSON-выгрузке. Текст
раскрывает кавычки 1С и сохраняет пробелы/Unicode/переносы строк.

Примеры содержимого Data:

```json
{"Name":"","CurrentOSUser":"test-computer\\test-user","AuthenticationMethod":"1"}
```

```json
{"Vendor":"FixtureVendor","Version":"9.8.7"}
```

```json
{"Data":{"Column":[{"name":"Свойство"},{"name":"Значение"}],"Row":{"Свойство":"Право","Значение":"Администрирование"}}}
```

Подтип 518 не распространяется автоматически на другие варианты аутентификации.
Для AuthenticationError отдельно проверен подтип 513. Декодирование Z ограничено
строковыми ячейками и проверенными описателями колонок. Иные типы/описатели,
нарушенная форма и повторяющиеся имена сохраняются резервным способом.

## Неизвестные и измененные форматы

Неизвестный тип Data, подтип P, другое событие или дополнительные элементы
известной формы получают версионированный конверт:

```json
{"$format":"1c-brackets-v1","nodes":["P",["999",["N","12345678901234567890123456789012345678"],["S",""],["U"]]]}
```

`nodes` содержит все узлы, возвращённые разбором скобочного блока:

- Блоки сохраняются массивами, включая пустые; порядок и вложенность сохраняются.
- Листья сохраняются строками: теги, номера подтипов, точные числовые токены,
  пустые строки и удвоенные кавычки не отбрасываются и не преобразуются в числа.
- U сохраняется как узел `["U"]`, а не пропадает из массива.

Это сохранение **разобранного дерева**, а не побайтовая копия LGP. Существующий
разбор удаляет внешние кавычки и форматирующие пробелы между узлами;
резервный формат не восстанавливает их. Листья здесь намеренно содержат исходные
удвоенные кавычки, тогда как именованные поля содержат декодированный текст.

Режим не меняет представление корректных корневых S/N/D/B/R/U: ими управляет
прежний контракт и отдельный `UseCorrectedValueParsing`. Дополнительные поля LGP,
разделители данных и диагностика включаются отдельно через новые настройки,
описанные в [контракте контекста и строгого разбора](noncorp-parsing.md).
CORP и неподтверждённые системные форматы требуют своих примеров.

## Проверки и запросы

Проверки через публичный reader покрывают известные формы, пустые поля, точные
числовые токены в резервном формате, вложенные неизвестные типы, экранирование,
измененную длину блока, неподдержанные таблицы, независимость настроек и
восстановление со старого курсора через ротацию.

Локально собраны два настоящих набора по 32 события на 8.3.27.2325. Второй создан
в новой изолированной базе с непустыми FixtureVendor/9.8.7, чтобы проверить порядок
Vendor/Version. Во всех четырех комбинациях настроек прочитано 64/64 события,
позиции одинаковы; 12/12 сложных Data совпадают со штатным JSON при Structured=true.
При обоих true также совпадают сравниваемые скалярные Data, Comment и статусы.
Для исходных 32 событий при обоих false полностью совпал результат всех 24 полей
с сохраненным baseline. Это не полная семантическая сверка всех полей со штатной
выгрузкой платформы.

Оригиналы журналов с именами машины/пользователя остаются локальными. Открытые
тесты используют искусственные записи с проверенными формами и ожидаемыми полями.

На ClickHouse 26.8.15.10 LTS проверены запись именованных объектов и резервного
формата, восстановление позиции, неизменность `SHOW CREATE TABLE` и запросы:

```sql
SELECT JSONExtractString(Data, 'AuthenticationMethod') FROM EventLogItems WHERE isValidJSON(Data);
SELECT JSONExtractString(Data, 'Data', 'Row', 'Значение') FROM EventLogItems WHERE isValidJSON(Data);
SELECT JSONExtractString(Data, '$format') FROM EventLogItems WHERE isValidJSON(Data);
```

Набор тестов не доказывает доставку ровно один раз при авариях, корректность
Elasticsearch и покрытие всех событий/версий платформы.

Справочник SQL-функций: [официальная документация ClickHouse](https://clickhouse.com/docs/reference/functions/regular-functions/json-functions).
