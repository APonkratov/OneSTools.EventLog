# Восстановление после ошибок ClickHouse

Проверено на отдельном ClickHouse 26.8.15.10 LTS с production-драйвером
ClickHouse.Client 3.0.0.357. Сбой внедряет локальный HTTP-прокси; экспорт выполняют
настоящие циклы одиночной службы и Manager. Публичный журнал синтетический:
шесть событий, `Portion=2`, включён локальный checkpoint.
Полный локальный прогон: 439 тестов читателя и 95 тестов экспортера, без пропусков;
из них семь новых проверок относятся к подключению и восстановлению ClickHouse.
Production solution собирается успешно; прежние предупреждения о net5.0 сохранены.

| Сценарий | Курсор после ошибки | Результат автоматического восстановления |
| --- | --- | --- |
| Второй INSERT отклонён HTTP 503 до записи | Последнее событие первого пакета, Id=2 | Все шесть событий, каждое один раз |
| Второй INSERT записан, TCP-ответ оборван до получения клиентом | Id=2 | Все шесть событий; Id=3 и Id=4 повторены |
| Новый запуск после успешного завершения | Id=6, точный EOF | Ни одного нового INSERT |

Во всех сценариях сверяются уникальные позиции `(FileName, EndPosition)`,
содержимое событий и неизменность `SHOW CREATE TABLE`. Служба и Manager сохраняют
существующую задержку повтора пять секунд. В журнале ошибки теперь присутствуют
тип и текст первопричины, включая ответ ClickHouse; это видно и через FileLogger,
который не выводит отдельно переданный объект исключения.

## Исправления подключения

- Соединение считается готовым только после полного создания БД и таблицы.
  При ошибке или отмене подготовки оно закрывается; следующий вызов повторяет
  всю подготовку. Раньше ошибка CREATE TABLE оставляла открытое соединение, и
  последующие вызовы обращались к отсутствующей таблице.
- `Database` извлекается штатным `DbConnectionStringBuilder`, с учётом регистра
  ключа и кавычек значения. Первое подключение не выбирает ещё не созданную БД.
  Прежний код мог выбрать отсутствующую БД при другом регистре ключа или создать
  другое имя из-за кавычек. Нормализация самого имени БД сохранена.

Оба дефекта воспроизведены новыми тестами на прежнем коде. Исправления не меняют
24 колонки, DDL, движок, ключи, порядок значений INSERT и production-зависимости.
Новых настроек нет. Дополнительный ASP.NET Core framework используется только
тестовым проектом для локального прокси.

## Условия и ограничения

Для защиты от пропусков при частичной записи нужен постоянный локальный
`CheckpointFile` либо `CheckpointDirectory` у Manager. Сохраняются JSON и `.lock`;
исходные ЖР должны быть доступны до подтверждения доставки. Настройки остаются
необязательными ради совместимости. Старый режим восстановления из максимальной
позиции БД сохраняет риск пропуска начала частично записанного пакета.

Потерянный ответ INSERT не позволяет установить, был ли пакет записан. Экспортер
повторяет его, поэтому сохраняет события, но допускает дубли неподтверждённого
пакета. Гарантии exactly-once и дедупликации эта доработка не добавляет.

Проверены HTTP 503 и обрыв ответа после подтверждённой записи на сервере.
Аварийное убийство процесса, потеря питания, сетевое разделение, падение самого
ClickHouse и заполнение диска не проверялись. Нет утверждения о сохранности при
любой аварии. Постоянные ошибки прав, схемы или конфигурации по-прежнему вызывают
повтор через пять секунд; классификация таких ошибок остаётся отдельной задачей.

Разработка продолжается в одной ветке `codex/improve-eventlog-exporter` и
[одном PR #12](https://github.com/APonkratov/OneSTools.EventLog/pull/12).
Общие правила доставки описаны в [export-delivery.md](export-delivery.md).
