# Оптимизация чтения ЖР: до и после

На прежнем корпусе **452 190 событий** время чтения уменьшилось на **15%**
в default и при исправленном/структурированном Data, на **41%** при всех пяти
дополнительных флагах и на **34%** при добавлении полного контекста.
Это сравнение с предыдущей версией нашего форка; первоначальные измерения
апстрима приведены в [предыдущем отчёте](performance-2026-10-11.md).

## Изменения

- `LgfReader` и `EventContextReader` проверяют размер LGF перед каждым событием,
  но при совпадении размера с потреблённой байтовой позицией возвращаются сразу.
  Повторное чтение EOF и создание пустых объектов парсера исключены. Интервала
  опроса нет; дописывание проверяется при следующем чтении события. Независимые
  словари сохранены, чтобы контекст не менял прежнее разрешение имён.
- `Utf8BracketsReader` декодирует запись непосредственно из входного буфера,
  если она помещается в его оставшуюся часть. Для записи через границу буфера
  временный `MemoryStream` заполняется блоками вместо `WriteByte` для каждого
  байта и освобождается после записи. Объект строгой кодировки UTF-8 используется повторно.
- Курсор продолжает считать исходные байты. Неполная запись возвращает позицию
  к открывающей скобке, включая разорванный UTF-8. Сохранены лимит вложенности,
  обработка отмены, усечения LGF и откат при ошибке. Большие записи не создают
  дополнительного постоянно удерживаемого буфера.

Публичные модели, настройки, значения полей и формат checkpoint не изменены.
Изменений зависимостей, целевых runtime и структуры ClickHouse нет. Итог
транзакции не ожидается; `UseFinalTransactionStatuses=false` во всех замерах.

## Методика

До — код `87e8c3d` (production-reader соответствует `e574880`), после — изменения
этого PR. Старые бинарные файлы сохранены до изменений. Обе сборки проверены
заново в одной серии; прежние числа из отчёта не подставлялись в сравнение.

Те же девять снимков, 42 LGP + девять LGF, 83 951 154 байта. Windows 11 Pro,
Ryzen 7 7735HS, Release, .NET 8.0.31 x64, workstation GC,
`DOTNET_TieredCompilation=0`, `DOTNET_gcServer=0`, Europe/Moscow,
`LiveMode=false`. Кэш прогрет. Другие приложения не останавливались.

По семь измерений каждой сборки в каждом из шести режимов: **84 измерения**.
Каждый процесс выполняет полный прогрев и один измеряемый проход; порядок
версий и режимов чередуется. В таблице медианы; все выбросы оставлены в исходных
результатах и диапазонах. Компиляция, запуск процесса и прогрев вне таймера;
создание/освобождение reader и разрешение словарей включены.

Это сравнение библиотек под общим .NET 8, а не точный замер production-службы
под .NET 5, холодного диска или сетевой папки.

Суммарные управляемые выделения уменьшились во всех режимах. Пик процесса
не уменьшился одинаково во всех режимах: он включает прогрев, JIT, нативную
память и зависит от работы GC. Это не размер постоянно удерживаемой кучи.

## Чтение вместе с записью в ClickHouse

Выделенный Docker ClickHouse 26.8.15.10 LTS, закреплённый по digest. По три
измерения каждой версии в каждом режиме с чередованием порядка: 18 измерений.
Перед каждым — отдельный прогревочный проход. Пакеты 10 000, одна запись
одновременно, прежний ClickHouseStorage и 24 колонки. Создание соединения/таблицы,
проверки и удаление временной БД вне таймера; чтение, сериализация, INSERT
и ожидание подтверждения внутри. Это последовательный reader + storage;
планирование фоновых очередей службы не измеряется.

| Режим | До, с | После, с | Сокращение времени | Диапазон до / после, с |
| --- | ---: | ---: | ---: | ---: |
| Default | 9,409 | 9,123 | 3,0% | 9,326–9,974 / 9,110–9,183 |
| Data | 9,652 | 9,317 | 3,5% | 9,575–9,769 / 9,173–9,919 |
| Полный контекст | 14,188 | 12,259 | 13,6% | 14,063–14,250 / 12,077–12,367 |

При записи основной выигрыш получен в режиме контекста. В default/data
ускорение reader занимает меньшую долю общего времени. Серия из трёх измерений
даёт ориентир; в Data диапазоны пересекаются, поэтому небольшое изменение
медианы следует оценивать с учётом разброса.

Все проходы сохранили ровно 452 190 строк. Число колонок и SHOW CREATE TABLE
проверены после каждой записи. Временные БД, тестовый контейнер и его временный
том удалены.

## Проверка совместимости

- **418 reader-тестов + 74 интеграционных**, без пропусков. Решение целиком
  собирается; контракт ClickHouse проверен на реальном LTS. CI для изменения
  production-кода прошёл на Windows, Linux и ClickHouse.
- Во всех **шести режимах** выполнено отдельное полное сравнение сериализованных
  EventLogItem с замороженной сборкой до оптимизации: по 452 190 событий,
  **ноль различий во всех полях**, включая Data, Id и обе байтовые позиции.
  Сравнение не включено в таймер и сильнее агрегатного checksum бенчмарка.
- Повторная проверка по нативной выгрузке 1С и исходным деревьям: 9 079 записей
  фиксированных именованных форм, 6 521 самоописываемая, 50 позиционных;
  106 пустых P сохраняют полный fallback. Разделение сверено для 432 796 событий.
  Проверены 60 точек возобновления; SHA-256 всех 51 файла снимков совпали.
- Новые регрессии покрывают UTF-8, удвоенные кавычки и скобки на границах буфера,
  завершение записи ровно на границе, повтор неполной длинной записи, обновление
  контекста в live/archive, дописывание и усечение LGF после EOF, восстановление
  после неполного LGF в строгом режиме.
