# Исправление значений ЖР

Исправление значений действует всегда, без конфигурационного переключателя.
[Правила перехода](defaults-and-upgrade.md). Существующие 24 поля, ClickHouse DDL,
порядок вставки и формат позиции сохраняются.

## Контракт разбора

| Значение/поле | Исторический результат | Новый результат |
| --- | --- | --- |
| Data, тип N | Пустая строка | Исходный числовой токен с точкой, без преобразования в double/decimal и потери точности |
| Data, тип D | Пустая строка | `yyyy-MM-ddTHH:mm:ss`, без смещения часового пояса |
| Data, тип S | Обрезанные краевые пробелы, удвоенные кавычки | Точная строка: пробелы, переносы строк, раскрытые кавычки |
| Comment, DataPresentation и текстовые значения из LGF | Удвоенные кавычки | `""` раскрываются в `"`; пробелы сохраняются |
| TransactionStatus U | Зафиксирована | Не завершена |
| TransactionStatus C | Отменена | Зафиксирована |
| TransactionStatus R | Не завершена | Отменена |

Дата внутри Data — значение 1С без часового пояса. Время самого события и время
транзакции продолжают преобразовываться по существующей настройке TimeZone.
TransactionStatus N, Data типов B/R/U и существующие представления системных
событий сохраняют прежний контракт. Для неизвестных кодов событий остается
исходное имя, с раскрытыми кавычками в новом режиме.

Сложные и неизвестные данные всегда сохраняются в [структурированном формате](structured-data.md).
Дополнительные поля и разделители можно включить отдельным UseEventContext.

## Совместимость

Схема БД сохраняется; значения Data, TransactionStatus и строк с кавычками меняются.
Переключения обратно на исторический разбор нет. Подтверждённая история сохраняется,
миграция или повторная загрузка автоматически не выполняются. Старый курсор принимается.

## Проверки

- Регрессионные тесты через публичный EventLogReader проверяют штатный разбор,
  числа до 38 цифр, малые дроби, даты, Unicode/кавычки/пробелы, статусы,
  сохранение сложных данных и продолжение со старой позиции через ротацию LGP.
- Проверки обоих конструкторов EventLogExporter доставляют события в тестовый
  приемник с новым поведением, в том числе при оставшихся удалённых ключах false,
  true и невалидном значении: ключи игнорируются.
- На ClickHouse 26.8.15.10 LTS проверены запись исправленных значений в старую
  таблицу и неизменность ее схемы; также выполняются прежние контрактные тесты.
- Локальная сверка настоящего ЖР 8.3.27.2325 со штатной JSON-выгрузкой ibcmd:
  32/32 события в обоих режимах; все 24 поля исторического результата идентичны
  baseline при false. При true устранены 6 скалярных расхождений, 1 расхождение
  комментария и 4 расхождения статуса. Сложные системные записи обрабатываются
  без отдельного переключателя. Оригиналы с именами
  компьютера/пользователя не публикуются;
  открытые тесты используют искусственные записи с теми же типами значений.

CORP-покрытие ожидает отдельного набора файлов от пользователя.
