# Явно включаемое исправление значений ЖР

`UseCorrectedValueParsing` по умолчанию равен `false`. Отсутствующая настройка и
явное `false` сохраняют историческое поведение парсера. Существующие 24 поля,
ClickHouse DDL, порядок вставки и формат позиции не меняются.

В одиночном экспортере и Manager настройка находится в разделе `Exporter`:

```json
{
  "Exporter": {
    "UseCorrectedValueParsing": true
  }
}
```

Это фрагмент для добавления в существующую конфигурацию. В библиотеке используется
`EventLogReaderSettings.UseCorrectedValueParsing`, в программном экспортере —
`EventLogExporterSettings.UseCorrectedValueParsing`.

## Контракт включенного режима

| Значение/поле | Исторический результат | При `true` |
| --- | --- | --- |
| Data, тип N | Пустая строка | Исходный числовой токен с точкой, без преобразования в double/decimal и потери точности |
| Data, тип D | Пустая строка | `yyyy-MM-ddTHH:mm:ss`, без смещения часового пояса |
| Data, тип S | Обрезанные краевые пробелы, удвоенные кавычки | Точная строка: пробелы, переносы строк, раскрытые кавычки |
| Comment, DataPresentation и текстовые значения из LGF | Удвоенные кавычки | `""` раскрываются в `"`; пробелы сохраняются |
| TransactionStatus U | Зафиксирована | Не завершена |
| TransactionStatus C | Отменена | Зафиксирована |
| TransactionStatus R | Не завершена | Отменена |

Дата внутри Data — значение 1С без часового пояса. Время самого события и время
транзакции продолжают преобразовываться по существующей настройке TimeZone.
TransactionStatus N, Data типов B/R/U и существующие представления системных
событий сохраняют прежний контракт. Для неизвестных кодов событий остается
исходное имя, с раскрытыми кавычками в новом режиме.

При `UseStructuredDataParsing=false` сложный Data типа P сохраняет старое
представление `Item n: ...`, включая старое декодирование вложенных значений.
Имена полей и часть данных таких системных событий по-прежнему теряются.
Независимый [режим сложных данных](structured-data.md) сохраняет P и неизвестные
типы в JSON. Разделители данных, дополнительные поля LGP и записи LGF неизвестных
типов этими режимами не исправлены.
Поврежденные записи также не являются предметом этого режима.

## Совместимость и включение

Схема БД совместима в обоих режимах. При `true` изменяются **значения** Data,
TransactionStatus и строк с кавычками; существующие фильтры и отчеты следует
проверить перед включением. Режим применяется только к последующим прочитанным
событиям и автоматически не переписывает ранее выгруженные строки. Сохраненную
позицию старого режима можно использовать в новом; байтовые смещения одинаковы.

Отключение настройки возвращает прежнее декодирование последующих событий.
Уже записанные значения сохраняются: в одной таблице могут оказаться данные
обоих режимов. Автоматическая миграция или повторная загрузка не выполняются.

## Проверки

- Регрессионные тесты через публичный EventLogReader проверяют оба режима,
  числа до 38 цифр, малые дроби, даты, Unicode/кавычки/пробелы, статусы,
  прежнее представление P и продолжение со старой позиции через ротацию LGP.
- Проверки обоих конструкторов EventLogExporter доставляют события в тестовый
  приемник при отсутствующей настройке, false и true.
- На ClickHouse 26.8.15.10 LTS проверены запись исправленных значений в старую
  таблицу и неизменность ее схемы; также выполняются прежние контрактные тесты.
- Локальная сверка настоящего ЖР 8.3.27.2325 со штатной JSON-выгрузкой ibcmd:
  32/32 события в обоих режимах; все 24 поля исторического результата идентичны
  baseline при false. При true устранены 6 скалярных расхождений, 1 расхождение
  комментария и 4 расхождения статуса. Сложные системные записи обрабатываются
  отдельной настройкой `UseStructuredDataParsing`. Оригиналы с именами
  компьютера/пользователя не публикуются;
  открытые тесты используют искусственные записи с теми же типами значений.

CORP-покрытие ожидает отдельного набора файлов от пользователя.
